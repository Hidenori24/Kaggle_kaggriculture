# ブランチ・提出運用

## ブランチの役割

| ブランチ | 用途 | Kaggle提出 |
| --- | --- | --- |
| `feature/*` | テストや小規模な開発 | しない |
| `experiment/*` | 改善候補の評価 | しない |
| `baseline/*` | 安定版の凍結保存 | しない |
| `main` | テスト済みコードの統合 | しない |
| `submission` | 意図的に選んだ提出候補 | pushで実行 |

## 安定版と改善版

現在の最高スコア版は `baseline/score-<score>` とタグで保存する。改善候補は必ず実験ブランチで評価し、安定版を直接変更しない。

提出候補は次のゲートを通過させる。

1. `python -m pytest -q`
2. 3エピソード以上の必須シミュレーション
3. 拡張シード比較と過去の敗戦ケースの回帰確認
4. タイムアウト・不正行動・パッケージ形式の確認
5. コミットSHAとパッケージSHA-256の記録

## 最新2件の運用

Kaggle側で最新提出が評価対象になる場合に備え、提出は「安定版」と「検証済み改善版」の組み合わせを基本とする。未検証候補は提出しない。提出後に候補が悪かった場合、提出枠を消費せずに取り消せるとは限らないため、先にActionsの全ゲートを通す。

提出後は、コミットSHA、提出ID、提出結果、スコアを `docs/experiments.md` に記録する。安定版は改善候補の結果にかかわらず保持する。

## Actionsの境界

- `ci.yml`: `main`、`feature/**`、`experiment/**`、`baseline/**` の検証。
- `submit.yml`: `submission` への意図的なpushだけで提出処理を開始。
- 同時提出、同一コミットの二重提出、Secret未設定、テスト失敗、制限超過は停止する。
