# 強者リプレイから導く実装方針

## 1. 観測結果

`90041552.json` と `90073673.json` は、参加者名は異なるが行動系列がほぼ同じだった。したがって、単発の幸運ではなく、再現性のある生産ラインとして扱う。

| 要素 | 強者リプレイの共通傾向 | 現行ベースライン |
| --- | ---: | ---: |
| 報酬 | 約110,000 / 約164,000 | 約27,000〜28,000 |
| HIRE | 約304〜306 | 最大6/日 |
| BUY_LAND | 2回 | なし |
| BUY_ANIMAL | 牛8、羊6 | なし |
| BUY_SEED | WHEAT 66、STRAWBERRY 44、MELON 21 | MELON中心 |
| BUY_PRODUCT | 約277〜315 | なし |
| 動物系 | FEED / CARE / COLLECT_FERTILIZER | なし |
| 農作業系 | FERTILIZE / HARVEST / SELL | 一部のみ |

強者の中心は「作物を植える農家」ではなく、雇用者を含む多数のユニットで、作物・動物・市場を同時に回す農場経営である。

## 2. 実装方針

### Phase A: 既存版を壊さない共通基盤

- `BaselineConfig` に戦略パラメータを集約する。
- 観測値が欠落している場合は、現在のメロン栽培へ安全にフォールバックする。
- 各ユニットに固定の役割と巡回目標を割り当て、同じ場所でPASSし続けない。
- 市場注文は、現在資金・在庫容量・当日の雇用費を確認してから出す。

### Phase B: 強者ラインの最小再現

1. 初期資金から無理のない範囲で雇用する。
2. 収穫利益が蓄積した後、`BUY_LAND` を1,000、次に2,000の順で実行する。
3. パスチャーを建設し、牛・羊を購入して配置する。
4. WHEATを飼料として購入し、動物のFEED/CAREを毎日行う。
5. 肥料を回収し、成熟前の高価値作物へFERTILIZEする。
6. 収穫物と不要在庫をSELLし、WHEAT・種・動物へ再投資する。

### Phase C: 評価と採用

- 既存ベースラインを比較対象として固定する。
- 少なくとも10シードで、平均・中央値・最小値・無効行動数を比較する。
- 平均だけでなく、無効行動やPASS偏重が増えていないことを採用条件にする。
- 現行版を安定して上回った場合だけ `main` に反映する。
- Kaggle提出は `submission` ブランチへ明示的に反映する段階で別途実施する。

## 3. 重要なSDK制約

- 土地価格は追加区画の順に 1,000 / 2,000 / 4,000。
- HIRE費用は当日の人数に応じた Fibonacci 系列。
- `BUY_PRODUCT` は WHEAT と FERTILIZER が対象で、購入品はshedに入る。
- 動物は対応する PASTURE/COOP 上に `PLACE` する必要がある。
- FEED は WHEAT を1個消費し、CARE と別々の行動である。
- `COLLECT_FERTILIZER` は動物タイル上でのみ有効。
- `PLACE` のshed投入はshed隣接マスでのみ有効。

## 4. リスクと対策

- **資金枯渇**: 雇用・土地・動物・種を同時購入せず、段階ごとに現金リザーブを設ける。
- **行動の無効化**: 位置・タイル・在庫を確認し、未対応の観測ではPASSまたは移動へ落とす。
- **新規土地の移動失敗**: 区画ごとにルートを分け、未開放タイルを目標にしない。
- **餌不足**: 動物数から必要WHEAT量を算出し、shed容量も確認する。
- **強者再現の過学習**: リプレイの行動数をそのまま固定せず、価格・資金・残日数から調整する。

## 5. 2026-08-20: 終盤経済オーバーライド計画

94410438の敗戦では、実行失敗やタイムアウトではなく、20日目以降に固定テープの経済構成が相手に遅れた。
自分はBUY_SEED 18回・BUY_PRODUCT WHEAT 233回・FEED 314回だったのに対し、相手はBUY_SEED 58回・BUY_PRODUCT WHEAT 135回・FEED 290回で、MILK売却量は自分237個に対して403個だった。
この差を根拠に、既存テープを18日目までは維持し、終盤だけ状態依存の上書きを試す。

### 実装順序

1. `EconomicState`を追加し、day/step、cash、animal count、WHEAT/FERTILIZER在庫、seed在庫、shed占有率、market price、残りFEED/FERTILIZE需要を観測から抽出する。
2. `EconomicGuard`を追加し、次を満たさない場合は必ず従来テープへ戻す。
   - day 18〜24の範囲内
   - 飼料と肥料の安全在庫を確保済み
   - shed占有率80未満
   - 雇用費・既存作業費を含む現金リザーブを確保
3. 第1候補は「新規動物購入を抑制し、空いた市場注文枠でWHEAT種を少量購入する」だけに限定する。作物作業の大規模な再計画は同時に入れない。
4. 第2候補として、WHEAT購入が将来需要を超える場合だけ、一部をWHEAT種購入へ置換する。残り日数で収穫まで回収できない場合は置換しない。
5. 最終5日間は新規投資を禁止し、収穫・売却・必要な給餌へ戻す。

### 評価条件

- 現行候補 `507443b`、安定参照 `242aea1`、immutable baseline `origin/baseline/score-1882`を比較対象として固定する。
- 通常シミュレーション3回、head-to-head 16 seed×両席、敵対ベンチ8戦を同一条件で実行する。
- 94410438では、day 20以降の現金差、BUY_PRODUCT WHEAT回数、BUY_SEED回数、MILK/FERTILIZER収量を比較する。
- 無効行動、動物の餓死、shed満杯固定、既存版比1%以上の平均報酬低下が1つでもあれば不採用とする。
- head-to-headで安定参照に対して勝率75%未満、または平均マージンが負の場合は提出しない。

### ロールバック方針

候補は `experiment/economic-overlay-20260820` 上でのみ評価する。採用する場合だけ `main`へPRを作成し、さらに`submission`へ明示的に反映する。現行の提出候補と履歴記録は変更せず、候補が弱ければブランチを破棄する。
