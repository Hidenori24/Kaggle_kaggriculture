# ベンチマーク相手

`opponents.json` は、実際のKaggriculture対戦（公開エピソードリプレイ）から**相手側の行動列だけ**を抽出し、
zlib+base85で圧縮して保持したものです。`scripts/benchmark.py` がこれを再生して固定相手として使います。

## なぜ必要か

| ハーネス | 相手 | 市場価格 | 価格依存の変更を測れるか |
| --- | --- | --- | --- |
| `scripts/simulate.py` | `random` | ほぼ下落しない | **測れない**（分岐が発動しない） |
| `scripts/selfplay_eval.py` | 自分自身 | 中程度に下落（MELON→約106） | 部分的にしか測れない |
| `scripts/benchmark.py` | 実対戦の記録相手 | 実ラダー相当まで下落 | 測れる |

PR #10 の価格フロアは、`simulate.py` では分岐がほぼ発動しないため導入前後で約19万点と変わらず「安全」に見えたまま、
実ラダーで約900点の後退を出しました。同じ失敗を繰り返さないために、市場側の変更はこのベンチマークで測ります。

## 解釈の注意

- **相手の再現ではありません。** 記録された行動は相手が実際に見た盤面に対して選ばれたもので、別のポリシーへ再生すると
  農場側の行動は一部無効になります。したがって相手はここでは本来より弱く振る舞います。
- **リーダーボードの予測でもありません。** 絶対値には意味がありません。比較してよいのは
  「同じ相手テープに対する候補版どうしの自分の報酬」だけで、上の表の相手スコアと比べてはいけません。
- 相手テープが固定かつ環境が決定的なので、**変更前後の差分は変更に帰属できます**。これが唯一の存在理由です。

## 再生成

`scripts/benchmark.py` はこのJSONだけを読みます。元のリプレイJSON（1件約30MB）はリポジトリに含めません。
新しい相手を追加する場合は、リプレイの `steps[i][opponent_seat]["action"]` を全ステップ集めて
`json -> zlib.compress -> base64.b85encode` し、`actions_b85_zlib` として同じ形式で追記してください。
